# TypeScript 回顾资料规划

## Summary
在这个空目录里搭建一套“可执行的 TypeScript 知识回顾材料”，按“从 JavaScript 延伸到 TypeScript，再到 TypeScript 独有能力”的顺序组织。最终产物不是单一笔记，而是一组按主题拆分的 `.ts` 示例文件，配合一份总览文档，方便你一边运行代码一边理解规则、边界和常见误区。

## Key Changes
1. 建立一份总览入口文档，说明学习顺序、每个模块的目标、建议阅读方式，以及各示例文件之间的关系。
2. 按主题拆分示例文件，每个文件聚焦一个知识点或一个紧密相关的小模块，文件内使用“示例代码 + 精简注释”的讲解型结构，而不是只写概念定义。
3. 内容顺序按“从 JS 到 TS”展开，建议分为这些模块：
   - 基础类型与类型标注：`number`、`string`、`boolean`、数组、元组、对象、函数参数与返回值。
   - 类型推断与类型收窄：推断规则、联合类型、字面量类型、控制流分析、`typeof` / `instanceof` / `in`。
   - JavaScript 常见结构的 TypeScript 化：函数重载、可选参数、默认参数、解构、对象与数组操作的类型表达。
   - TypeScript 独有核心：类型别名、接口、枚举的定位与替代方案、泛型、约束、默认泛型参数。
   - 高级类型系统：交叉类型、映射类型、条件类型、索引类型、`keyof`、`extends`、`infer`、工具类型。
   - 面向对象相关：类、访问修饰符、抽象类、实现接口、`readonly`、参数属性。
   - 模块与工程化基础：`import` / `export`、模块解析的基本认知、`tsconfig` 核心配置、编译目标与严格模式。
   - 与外部 JS/库协作：声明文件、第三方类型、`any` / `unknown` / `never` 的区别与使用边界。
4. 每个模块文件都采用统一结构：
   - 文件开头写该知识点解决什么问题。
   - 中间给最小可运行示例，展示正确写法和典型边界。
   - 结尾补充“易混点 / 常见误区 / 和 JavaScript 的差异”。
5. 工程化部分只覆盖基础核心，不扩展到框架专项内容；不默认加入 React/Vue/Node 专题，避免第一版范围失控。

## Public Interfaces / Structure
1. 目录结构会明确区分“总览文档”和“示例代码”两类内容。
2. 示例代码的公共约定如下：
   - 每个知识点对应独立 `.ts` 文件，文件名使用有序前缀，保证阅读顺序稳定。
   - 文件内容默认可直接执行或至少可直接被 `tsc` 检查，不做只读伪代码。
   - 如需工程配置，会补一个最小可用的 `tsconfig.json`，只服务于这些教学示例。
3. 总览文档会作为唯一入口，列出每个文件的学习目标和建议先后顺序，避免你在文件之间跳转时失去上下文。

## Test Plan
1. 每个示例文件都应满足两类验证：
   - 运行时行为可观察：需要输出的示例能直接运行看到结果。
   - 类型行为可观察：需要报错或限制的示例能清楚体现 TypeScript 的检查目的。
2. 整体材料完成后，应至少覆盖这些场景：
   - 能区分“JavaScript 原有能力”和“TypeScript 增加的约束/表达能力”。
   - 能解释联合类型、泛型、接口、类型别名、映射类型、条件类型这些核心概念的用途。
   - 能通过最小工程配置跑通示例并理解严格模式的价值。
   - 能识别 `any`、`unknown`、`never`、类型断言、非空断言的使用边界。
3. 验收标准：
   - 你只看目录和入口文档，就能知道应该从哪个文件开始。
   - 你打开任意一个模块文件，都能看懂该知识点的目标、规则和示例。
   - 学完一轮后，能建立一张从“JS 写法”过渡到“TS 类型建模”的完整心智图。

## Assumptions
1. 第一版目标是“系统回顾 TypeScript 语言与基础工程化”，不是面向具体业务项目落地。
2. 内容深度以“重新建立完整认知框架”为主，不追求一开始就覆盖极少见的类型体操技巧。
3. 示例文件默认采用讲解型风格，不以内嵌练习题为主。
4. 工程化范围默认包含 `tsconfig`、模块系统、声明文件、编译与严格模式，但不扩展到框架类型细节。
